# SANEXT: управление опросами

Кабинет организатора: `/results`, первый вход по `ADMIN_PASSWORD`, далее — по паролю, установленному в кабинете. Главная `/` показывает открытые опросы; ссылка на конкретный опрос: `/?survey=ID`.

## Обновление существующей установки

1. До обновления создайте резервную копию по инструкции в README.md. Сохраните `.env` и прежний Docker-том `survey_data`.
2. Замените исходники и пересоберите приложение обычной командой Docker Compose. Не удаляйте том и не меняйте имя Compose-проекта.
3. При первом обращении к базе приложение в одной транзакции создаст новые таблицы. Прежний опрос появится как «Маркетинг × Продажи · 2027», а все записи `responses` будут перенесены в `entries`. Исходная таблица `responses` сохраняется, повторная миграция не создаёт дубликаты.
4. Проверьте `/api/health`, вход в `/results`, число анкет и несколько ответов старого опроса. Сделайте новую резервную копию.

Старые подписанные сессии посетителей продолжают работать для исходного опроса. Неподписанный cookie с ID больше не предоставляет доступа к анкете. Старые административные токены недействительны — организатору нужно войти заново.

## Пароль администратора

В `/results` нажмите «Сменить пароль». Укажите текущий пароль и дважды новый (16–256 символов). Сервер хранит новый пароль как scrypt-хеш с солью в SQLite. После сохранения все прежние административные сессии отзываются, а текущему браузеру выдаётся новая сессия. Изменение сохраняется после перезапуска приложения и не прерывает сессии участников.

`ADMIN_PASSWORD` в `.env` используется для первоначального входа и восстановления доступа. Если пароль забыт, задайте в `.env` **другое** значение и пересоздайте приложение через Docker Compose `up -d`; это заменит пароль кабинета и отзовёт административные сессии. Неизменённое значение `.env` при обычном перезапуске не перезаписывает пароль из кабинета. Подпись новых сессий участников использует отдельный случайный секрет в базе. Подписи предыдущего формата автоматически обновляются при открытии опроса; до такого обновления смена исходного `.env` может потребовать восстановления локального черновика.

## Активные опросы и главная страница

Статусы: «Активен» (сбор открыт), «Неактивен · черновик» (сбор закрыт), «Неактивен · архив» (сбор закрыт, история сохранена). На карточке есть кнопки «Активировать» / «Выключить опрос» и перенос в архив. Несколько опросов могут быть активны одновременно.

Если активных опросов нет, посетитель видит заглушку «Сейчас нет активных опросов» с проверкой обновлений. При одном активном опросе открывается его форма; при нескольких — карточки для выбора. Ссылка «Все опросы» в форме возвращает к доступным опросам. Прямая ссылка на выключенный опрос не позволяет отправлять ответы.

## Ветвление и изображения

В редакторе каждого вопроса есть «Условие показа»: выберите любой вопрос выше, оператор и ответ. Поддерживаются «Равен / выбран вариант», «Не равен / вариант не выбран», «Содержит» и «Ответ заполнен». Для матрицы дополнительно выбирается строка. Сравнение текста «Содержит» не учитывает регистр; равенство учитывает регистр и игнорирует пробелы по краям.

Например: первый вопрос «Использовали каталог?» с вариантами «Да» / «Нет»; второй «Что улучшить в каталоге?» показывается только при «Да». Для альтернативной ветки добавьте вопрос с условием «Нет». Цепочки условий поддерживаются: если исходный вопрос скрыт, все зависимые вопросы тоже скрываются. Нельзя ссылаться на вопрос ниже или создавать циклы. Перед удалением исходного вопроса уберите или измените условия зависимых вопросов. Кнопка «Убрать условие» возвращает постоянный показ.

Скрытые обязательные вопросы не мешают отправке. При смене ответа скрывшиеся ответы исключаются из черновика, сохранения и статистики. В отчёте указано число анкет, к которым применима ветка; в таблице участника и Excel/CSV скрытые вопросы помечены «Не показывался по условию». Предпросмотр следует тем же условиям, что и форма участника.

«Картинка к вопросу» позволяет загрузить PNG, JPEG, WebP или GIF до 4 МБ и добавить описание. Файл сохраняется в SQLite, отображается в форме, предпросмотре и отчёте. Можно убрать картинку из текущего вопроса; в старых версиях она сохраняется. Изображения неактивных опросов и неопубликованных файлов доступны только организатору. JSON содержит файлы картинок (base64), а импорт переносит их на другой сервер. SQLite backup/restore сохраняет все изображения, версии и настройки доступа. Excel/CSV содержат ответы, PDF — печатное представление отчёта с изображениями.

## Создание и редактирование

- «Создать опрос»: название, подзаголовок, вступление, сообщение благодарности.
- Вопросы: один вариант, несколько вариантов, свободный текст или матрица оценок. Настраиваются обязательность, подсказки, варианты, строки матрицы, лимит выбора и исключающие варианты («Ничего не мешает» и подобные).
- Варианты и строки вводятся по одному на строку, без дубликатов. Лимиты: 60 вопросов, 100 вариантов/строк, 3000 символов на текстовый ответ.
- «Оформление»: основной цвет, фон и готовые палитры. Логотип и шрифт SANEXT сохраняются.
- «Предпросмотр»: можно заполнить поля без создания ответов в базе.
- Статус «Активен» открывает сбор; неактивный черновик и архив закрывают сбор и сохраняют данные.
- Текущий опрос можно редактировать и после появления ответов: изменять формулировки, типы и варианты, удалять и добавлять вопросы, менять их порядок. При сохранении изменений вопросов автоматически создаётся новая версия по той же ссылке. Старые анкеты и их вопросы остаются в истории. Нельзя удалить последний вопрос; максимум — 60 вопросов.
- Вступление, название, подзаголовок, благодарность, цвета и статус можно менять без новой версии вопросов. «Копия» по-прежнему создаёт отдельный опрос.
- При повторном открытии обновлённого опроса посетитель начинает анкету новой версии. Ответы на полностью неизменённые вопросы переносятся в новый черновик; прежняя анкета сохраняется. Изменённые и добавленные вопросы нужно заполнить заново. Черновики браузера хранятся отдельно для каждой версии.
- Из архива опрос можно вернуть в черновики или снова открыть сбор. Данные при этом не удаляются.

## Отчёты и выгрузки

В отчёте есть переключатель «Версия вопросов». По умолчанию показана текущая версия; старые версии сохраняют свои вопросы, анкеты и статистику. Выгрузки относятся к выбранной версии, номер версии указан в имени файла. Каждая версия имеет отдельный отчёт: показатели посещения и завершения, динамика отправок, рейтинги вариантов, составные диаграммы матриц, точные таблицы и текстовые ответы. По умолчанию учитываются завершённые анкеты; черновики включаются отдельно. Фильтры дат используют UTC, время в карточке участника — московское.

- **Excel (.xlsx)**: листы «Ответы» и «Статистика», закреплённая строка заголовков и автофильтры. Текстовые ответы записаны как текст, формулы из ответов не исполняются; показатели сводки записаны числами.
- **CSV ответов**: одна анкета на строку, UTF-8 с BOM, разделитель `;`, защита от формул.
- **CSV сводки**: количества, базы расчёта и проценты по вариантам и строкам матриц.
- **JSON v2**: определение опроса и отфильтрованные анкеты. Для полного переноса выбирайте «Ответы участников», все статусы, пустые даты и поиск.
- **PDF**: кнопка открывает печать отчёта; выберите «Сохранить как PDF». Печатный отчёт включает все варианты и текстовые ответы, даже если они свёрнуты на экране.

PDF использует фильтры отчёта: даты и черновики. Остальные выгрузки учитывают фильтры текущего представления. В отчёте это даты и переключатель черновиков, в участниках — даты, статус и поиск. Выгрузка JSON одного опроса не заменяет резервную копию всей базы.

Импорт старого JSON-массива и нового JSON v2 поддерживается прежней командой:

```bash
docker compose exec app node scripts/import-responses.mjs /data/import.json
```

До импорта один раз запустите обновлённое приложение. Совпадающие ID пропускаются; структура существующих версий не перезаписывается. Исторический JSON импортируется в свою версию, не заменяя текущий опрос. Старый массив импортируется только в исходный опрос. Импорт выполняется транзакционно и не обновляет существующие ответы. Резервная копия SQLite сохраняет все опросы, архив и ответы; скрипты backup/restore остаются прежними.

## Доступ и ограничения

Административная сессия случайная, хранится на сервере в виде хеша, действует восемь часов и отзывается при выходе. Токен не передаётся в JavaScript. Cookie имеет HttpOnly, SameSite=Strict и Secure при HTTPS. Смена пароля отзывает административные сессии; новые сессии участников от пароля администратора не зависят. Посетитель с устаревшей подписью может явно создать новую сессию и восстановить локальный черновик; старая запись остаётся в базе.

Лимиты сохраняются в SQLite: 30 попыток входа за 15 минут на приложение, 300 новых сессий в час, 180 сохранений за минуту на сессию. HTTP используется для локальной проверки; для публичного доступа используйте HTTPS. Размер JSON-запроса ограничен 100 КБ; картинки загружаются отдельным запросом до 4 МБ. Конфигурация рассчитана на один экземпляр приложения с локальным SQLite.

## Проверки разработки

Требуется Node.js 24 и зависимости из `npm ci`:

```bash
npm run typecheck
npm test
npm run build
npm run test:smoke
```

Тесты создают временную SQLite-базу с вымышленными данными. Они проверяют перенос старых ответов, доступ, подписи, отдельные опросы, неизменность отправленных анкет, архив, статистику, CSV/XLSX, JSON-импорт, резервное копирование и восстановление.


## Количество ответов при множественном выборе

В редакторе вопроса «Несколько вариантов» задайте минимум и максимум, например 2 и 5. Одинаковые значения требуют точного количества. Минимум 0 сохраняет только верхний лимит; обязательный вопрос всё равно требует хотя бы один ответ. У ранее созданных вопросов минимум не задан, их поведение сохраняется.

Участник видит диапазон, количество выбранных ответов и подсказку при достижении максимума. Минимум проверяется при переходе дальше и отправке; черновик допускает незавершённый выбор. Необязательный вопрос можно полностью пропустить. Исключающий вариант, например «Ничего не мешает», выбирается один и освобождает от минимального количества. У скрытого по условию вопроса количество ответов не проверяется.

При достижении максимума блокируются все невыбранные варианты, в том числе исключающие. Чтобы изменить выбор, сначала снимите один ответ. Пока лимит не достигнут, выбор исключающего варианта снимает остальные ответы.

В редакторе сначала расположены основные поля вопроса, а ниже — компактные раскрывающиеся блоки «Картинка к вопросу» и «Условие показа». Условие показа задаёт, при каком предыдущем ответе вопрос появится у участника; у первого вопроса доступен только показ всем. Настроенные блоки раскрыты, пустые свёрнуты.

Лимиты сохраняются в версии опроса и JSON-выгрузке, проверяются сервером и при импорте. Минимум не может превышать максимум или число обычных, не исключающих вариантов.

## Несколько вопросов на одной странице

В карточке вопроса найдите «Страница опроса» и выберите «На одной странице с предыдущим вопросом». Повторите для следующих вопросов, которые нужно объединить в группу. Выбор «Начать новую страницу» завершает предыдущую группу. Первый вопрос всегда начинает первую страницу. В заголовках карточек показаны номера страниц, а в предпросмотре — их границы.

Участник отвечает на все вопросы группы с общими кнопками «Назад» и «Далее». Перед переходом проверяются все видимые обязательные вопросы текущей страницы. Условия показа работают внутри страницы сразу при изменении ответа; полностью скрытые страницы пропускаются. Каждый вопрос сохраняет свой ответ, статистику и тип ввода.

Старые опросы продолжают показывать один вопрос на странице. Изменение группировки создаёт новую версию структуры; прежние ответы остаются в истории. Группировка сохраняется в JSON и резервной копии.

## Удаление вопроса в редакторе

Кнопка «Удалить» сразу убирает карточку из редактора. Закреплённое уведомление показывает название удалённого вопроса и число оставшихся; «Вернуть вопрос» отменяет последнее удаление, сохраняя другие правки. Чтобы применить удаление к опубликованному опросу, нажмите «Сохранить изменения». Прежние ответы остаются в истории версий. Если другие вопросы ссылаются на удалённый в условиях показа, уведомление предложит исправить эти условия или вернуть вопрос.

## Приветственный блок

В редакторе откройте вкладку «Приветственный блок». Предпросмотр рядом с настройками показывает ту же панель, что и участник опроса. Можно изменить надпись сверху, заголовок и описание независимо от названия опроса, выравнивание, размер заголовка и цвет текста, нижнюю подпись и символ, включить или убрать цветную полосу. Фон меняется на вкладке «Оформление».

Добавляйте до четырёх изображений PNG, JPEG, WebP или GIF размером до 4 МБ каждое. Доступны подписи, изменение порядка, удаление, размещение над или под текстом и показ целиком либо с обрезкой. Сохраните изменения кнопкой «Сохранить изменения». Сброс возвращает исходные тексты и оформление, убирая картинки из блока.

Изображения хранятся в SQLite, включаются в JSON-выгрузку и резервную копию. Публично доступны только картинки активных опросов. Правки приветственного блока не создают новую версию вопросов и не разделяют статистику. У старых опросов без настроек сохраняется исходное оформление.

## Проверка Docker и обновление

Для развёртывания Node.js на сервере не нужен: Node.js 24 включён в образ. Обновление с сохранением существующего тома:

```bash
docker compose up -d --build
```

При использовании комплектного HTTPS:

```bash
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
```

Пароль, изображения, опросы, версии и ответы хранятся в прежнем томе `survey_data`. Используйте прежнее имя Compose-проекта. При собственном Nginx задайте `client_max_body_size 5m;`, чтобы разрешить картинки до 4 МБ.

Повторная проверка из исходного проекта при запущенном Docker Engine:

```bash
npm run test:docker
```

Скрипту нужен Node.js на машине запуска и доступ к реестрам при первой сборке. Он собирает образ, проверяет HTTP-сценарии, перезапуск, импорт и backup/restore в отдельном проекте с временным томом, затем удаляет созданные тестовые ресурсы. Рабочий `.env` и производственный том не используются. Тестовые скрипты в production-образ не включены.
