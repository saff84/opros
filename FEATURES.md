# Возможности сервиса и обновление

## Приоритетное обновление

1. **Воронка прохождения.** В отчёте видны открывшие, начавшие и завершившие, посещённые страницы и последняя страница у тех, кто не завершил анкету более суток. Повторные посещения не увеличивают число участников. Условные страницы имеют собственную аудиторию. Для анкет, собранных до обновления, нет исторических событий страниц — начало оценивается по прежнему статусу.
2. **Источники и QR-коды.** В статистике раскройте «Ссылка с меткой и QR-код». Укажите источник и кампанию, скопируйте ссылку или скачайте PNG/SVG. Генерация локальная. Поддерживаются `source`, `campaign`, а также `utm_source`, `utm_campaign`. Источник фиксируется при первом открытии анкеты на устройстве, сохраняется при обновлении версии. Это атрибуция сессий, а не идентификация людей.
3. **Проверка и предпросмотр.** В редакторе есть вкладка проверки перед публикацией. Ошибки блокируют сохранение; предупреждения помогают проверить содержание, даты, картинки и настройки. Предпросмотр переключается между компьютером и телефоном шириной 390 px, поддерживает страницы, условия и проверку ответов. Ответы предпросмотра не попадают в статистику.
4. **Автоматические копии.** В Docker работает отдельный сервис `backup`, проверяющий расписание раз в минуту. По умолчанию копия создаётся каждые 24 часа и хранится 7 дней. В «Доступ и резервные копии» можно изменить интервал и срок хранения, создать копию сейчас, проверить последнюю успешную операцию и скачать файл. Копия включает SQLite целиком: опросы, версии, ответы, картинки, пользователей, источники и события. Она находится в том же Docker-томе: для защиты от потери диска сохраняйте скачанные копии отдельно.

## Остальные функции

- **Расписание опросов.** В редакторе задаются начало и окончание публикации. Время вводится в часовом поясе браузера, хранится в UTC. Статус должен быть «Активен»; вне периода опрос скрыт, изображения недоступны участникам, ответы не принимаются. Отдельный планировщик для открытия не нужен: доступность проверяется сервером при запросе.
- **Шаблоны.** В списке доступны готовые шаблоны удовлетворённости, обратной связи после мероприятия и потребностей команды. В статистике опроса есть «Сохранить опрос как шаблон». Пользовательские шаблоны хранятся в базе и доступны редакторам кабинета. При создании опроса ответы не копируются.
- **Типы вопросов.** Помимо текста, одного/нескольких вариантов и матрицы доступны шкала 1–10, звёзды 1–5, NPS 0–10, ранжирование и выбор изображения. Для NPS рассчитывается доля оценок 9–10 минус доля 0–6, диапазон −100…100. Для ранжирования меньшее среднее место означает более высокий приоритет. При заполнении ранжирования нужно расставить все варианты; необязательный вопрос можно пропустить.
- **Уточнение «Другое».** В карточке вопроса выберите вариант в настройке «Текстовое уточнение варианта». При его выборе открывается поле; текст обязателен для этого ответа и сохраняется в ответах и выгрузках. При снятии выбора скрытое уточнение удаляется из текущего черновика.
- **Сравнение.** В отчёте раскройте сравнение групп А и Б. Выберите периоды, отделы, регионы, источники или второй опрос. Используются отправленные анкеты и совпадающие по типу и вариантам вопросы. Показываются базы ответов и разница долей в процентных пунктах; это описательная статистика, а не проверка статистической значимости. Отдел и регион участник может указать добровольно перед началом.
- **Роли кабинета.** `admin` — существующий владелец; вход без логина также сохраняется. Новые пользователи получают отдельные логин и пароль. Администратор управляет доступом и копиями, редактор меняет опросы, наблюдатель только читает результаты и выгружает отчёты. Права проверяются на сервере. Смена прав/отключение закрывают сессии пользователя. Собственный пароль меняется через «Сменить пароль».
- **PDF-файл.** «PDF · отчёт с диаграммами» скачивает настоящий PDF с кириллицей, фильтрами, базами ответов, графиками, NPS и ранжированием. Текстовые ответы ограничены первыми 50 на вопрос; полный набор остаётся в Excel/CSV/JSON. Внешние сервисы генерации не используются.

## Обновление открытых опросов без сброса кэша

Публичная страница запрашивает актуальное определение без HTTP-кэширования каждые 5 секунд, при возвращении на вкладку и после сохранения в соседней вкладке кабинета. Изменение оформления не сбрасывает ответы. При изменении структуры автоматически загружается новая версия; удалённые вопросы исчезают. Совместимые сохранённые и несохранённые ответы переносятся, изменённые и новые вопросы требуют проверки. Прежняя анкета остаётся в истории. Появляется сообщение об обновлении.

Ранее загруженный код приложения при установке этого выпуска обновляется обычной перезагрузкой страницы. После этого изменения опросов обнаруживаются автоматически; принудительная очистка браузерного кэша не нужна.

## Docker

Сохраните прежнее имя Compose-проекта, `.env` и том `survey_data`. Новые таблицы создаются автоматически, прежние данные не удаляются. Новые зависимости закреплены lockfile. Next.js обновлён до 16.3.8.

```bash
docker compose -f docker-compose.yml -f docker-compose.https.yml config --quiet
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
```

В сервисе `backup` должен быть ровно один блок `healthcheck: { disable: true }`. Ошибка `mapping key "healthcheck" already defined` означает дубликат ключа в одном сервисе. В актуальном файле дубликат удалён.

При ручном восстановлении остановите **оба** сервиса, затем восстановите и запустите приложение:

```bash
docker compose stop app backup
docker compose run --rm --no-deps app node scripts/restore.mjs /data/backups/ИМЯ_КОПИИ.sqlite
docker compose up -d
```

Для установки с HTTPS во всех командах используйте те же `-f` параметры, что и при первоначальном запуске. Дополнительный публичный HTTPS-сертификат, DNS и firewall проверяются на сервере размещения.

## Проверки

```bash
npm test
npm run typecheck
npm run test:docker
npm run test:browser
```

Последняя команда выполняет Docker-проверку и сценарии в изолированном браузере. На Windows используется установленный Microsoft Edge. На Linux установите Chromium через `npx playwright install chromium` либо задайте `BROWSER_EXECUTABLE_PATH`. Тесты используют отдельные временные базы и Docker-проект; рабочие данные и `.env` не используются. Снимок мобильного предпросмотра сохраняется в `artifacts/mobile-preview.png`.
